## 插件操作实时进度展示 实施方案

**原理**:后端 `run_plugin_op` 执行期间通过 `Channel<PipelineEvent>` 推送事件,其中 `StepStarted{id,title}` 可携带任意标题文本;前端插件对话框的 `onEvent` 目前只收集输出行。让后端在逐个执行更新/卸载时发出 `item-*` 进度事件(标题即本地化的"正在更新插件(2/5):xxx"),前端顶部的忙碌 Alert 捕获后实时替换显示。

### 一、后端(lib.rs + i18n.rs)
- `plugin_update` 与 `plugin_remove` 统一改为**按 key 循环执行**(卸载与更新同构;每次仍包在一次 web 启停封装内),循环体发出 `StepStarted{id:"item-{i}", title:...}`:
  - 多个时标题:`正在更新插件（{i}/{n}）：{key}` / `正在卸载插件（{i}/{n}）：{key}`
  - 单个时:`正在更新插件：{key}` / `正在卸载插件：{key}`(无编号)
- Rust 侧 `i18n.rs` 新增 4 个键:`plugin.progress.updating(.one)`、`plugin.progress.removing(.one)`(中英)。
- 结果聚合逻辑维持上一轮实现的逐条聚合不变。

### 二、前端(PluginManagerDialog.tsx)
- 新增状态 `activityLine`;`onEvent` 中捕获 `stepStarted && id.startsWith("item-")` → 写入该状态;`runOp` 开始/结束时清空。
- 忙碌 Alert 渲染改为:`message={activityLine ?? t("plugin.busy.msg", {0: busyLabel})}`,图标换成 `LoadingOutlined spin`(旋转加载),旋转动画直观表达"进行中"。
- 安装按钮的 busyLabel 从泛泛的「安装插件」改为带输入内容的 `安装插件:{输入值}`(新前端 i18n 键,兼容现有"正在{0}…"外层模板)——安装是单命令多 spec,不拆分执行,用这种方式展示目标即可。

### 三、文档
两份 README §4 微调一句:操作时顶部实时显示"正在更新/卸载哪个插件"(批量含 N/M 进度)。
